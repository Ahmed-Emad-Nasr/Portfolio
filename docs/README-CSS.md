# تنضيف الـ CSS — النتايج والتطبيق

---

## أول حاجة، تصحيح مهم

**حجم ملف الـ CSS في الريبو مش مقياس أداء.**

Next بيـminify الـ CSS في build الإنتاج: التعليقات والمسافات والسطور
الفاضية بتختفي بالكامل. ١٧٪ من الـ ١٥٦ كيلوبايت بتاعتك تعليقات، وهي
بتكلّف الزائر **صفر بايت**. لو حد قاللك "صغّر ملفات الـ CSS عشان السرعة"
فهو بيوصف مشكلة مش موجودة عندك.

اللي **بيتقاس** فعلاً تلات حاجات:

1. **عدد القواعد** اللي المتصفح بيمرّ عليها في كل style recalculation
2. **تكلفة الرسم** للخصائص اللي اخترتها (`backdrop-filter` أغلى من
   `opacity` بمراحل)
3. **البايتس بعد الضغط** — والدوبليكيت هنا هو اللي بيتحسب، مش التعليقات

التنضيف اللي عملته مركّز على التلاتة دول. حصّلت كمان فايدة في القراءة،
بس دي مكسب جانبي مش الهدف.

## اللي اتلقى

شغّلت فحص على كل الـ ٢٥ ملف CSS. النتيجة:

| # | اللقطة | الحجم |
|---|--------|-------|
| ١ | متغيّرات CSS معرّفة ومحدش بيقراها | **٤٧ من ١١١ — ٤٢٪** |
| ٢ | كلاسات utility عامة مش مستخدمة في أي JSX | **١١** |
| ٣ | كلاسات معرّفة في module files ومش مستخدمة | **٨** |
| ٤ | هيدر البلوج والهيدر الرئيسي | **٩٨٪ نفس الملف** |
| ٥ | `transition` على `backdrop-filter` بملء الشاشة | **١** |
| ٦ | تصريحات `box-shadow: none` (أثر شيل الـ glow) | **١٦** |

ولقيت تلات باجات في الطريق:

**`content-visibility: auto` كانت شغّالة على الـ hero.** قاعدة `section`
العامة بتشمل `<section id="Home">`، اللي جواه صورة الـ LCP. كروم مبيحسبش
LCP لمحتوى جوه subtree متخطّى.

**قاعدة الـ mid tier مكانتش بتعمل اللي مكتوب في تعليقها.**
`animation-duration: calc(var(--anim-slow) * 1.5) !important` مكانش بيبطّأ
الأنيميشن — كان **بيساوي كل الأنيميشن الزخرفي على ٦ ثواني** مهما كانت
مدته. نبضة الـ badge (١.٦ث) والحلقة الدوّارة (٢٥ث) بقوا نفس المدة.

**`-webkit-clip-path` ناقص في هيدر البلوج.** شكل الـ trapezoid مكسور على
سفاري في صفحات البلوج بس — لأن الملف اتنسخ، واتصلّح في نسخة واحدة.

### `app/globals.css`

بديل كامل. النتايج المقاسة:

```
قبل:  24,508 بايت   91 قاعدة   315 تصريح   109 توكن (47 ميت)
بعد:  19,607 بايت   71 قاعدة   222 تصريح    62 توكن (0 ميت)
```

**تأكدت آلياً إن مفيش توكن حي اتشال** — قارنت كل `var(--x)` في الـ ٢٥ ملف
CSS وكل `--font-*` في ملفات الـ TS مقابل التعريفات الباقية.

أهم تعديلين جوّاه:

**المحدد العالمي بتاع `backdrop-filter` اتشال.** كان:

```css
html[data-tier="low"] *,
html[data-tier="low"] *::before,
html[data-tier="low"] *::after {
  backdrop-filter: none !important;
}
```

ده بيجبر إعادة حساب أنماط على كل عنصر في الصفحة. والموقع كله فيه **أربع**
تصريحات `backdrop-filter`، وكلهم بيقروا `var(--card-blur)` أو
`var(--ui-blur)`. تصفير التوكنين بيعمل نفس الشغل بصفر تكلفة.

**`* { will-change: auto !important }` اتشال.** الموقع فيه تلات تصريحات
`will-change`، اتنين منهم في المؤشر المخصص (ديسكتوب بس). محدد عالمي عشان
يلغي تصريح واحد غير ضار.

## اللي **مقلتش** أشيله

فيه حاجات ممكن تبان زيادة وهي مش كده:

**التعليقات العربية الطويلة.** مش بتوصل للزائر أصلاً، وبتوفّر عليك وقت
كل مرة ترجع للكود. سيبها.

**`.title` و`.title::before/::after` مكرّرين في ٥ ملفات، و`.section-*`
في ٣.** ده دوبليكيت حقيقي (~١.٥ كيلوبايت). ينفع يتشال بـ `composes` بتاعة
CSS Modules من غير أي تعديل في الـ JSX. سبته لأن المكسب صغير والتغيير
بيلمس ٨ ملفات — لو عايزه قوللي.

**`@media print`.** بورتفوليو بيتطبع فعلاً، وده كود ميّت بالنسبة لأداء
الشاشة (المتصفح مبيحسبش قواعد print وقت العرض العادي).

**كتلة الوصولية والـ `forced-colors`.** صفر تكلفة على العرض العادي.

## نقطة أهم من كل اللي فوق

الـ ٤٢٪ توكنز ميتة مجتش من إهمال — دي علامة إن نظام التوكنز اتبنى مرة
واحدة "لكل الاحتمالات" بدل ما يكبر مع الاستخدام. `--z-toast` و`--info`
و`--surface-overlay` كلها معرّفة لحاجات الموقع معملهاش.

`scripts/css-audit.mjs` موجود عشان ده تحديداً. شغّله قبل أي PR — أرخص من
إنك تكتشف بعد سنة إن نص نظام التصميم عندك مجرد ملاحظات.
