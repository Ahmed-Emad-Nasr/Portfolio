# الـ Verify وقع — إزاي تعرف السبب

## أول حاجة: هات اللوج

في الصورة اللي بعتها، الـ run فشل بعد 49 ثانية. المدة دي معناها إنه عدّى
الـ checkout والتثبيت ووقع في واحدة من الفحوصات.

افتح الـ run الأحمر، ادوس على الخطوة اللي جنبها ❌، وابعتلي آخر 20 سطر.
من غير كده أنا بخمّن.

## بس فيه غلطة تصميم مني، وصلحتها

النسخة الأولى من الـ workflow كانت بتقف عند **أول** خطوة تفشل. يعني إنت
تستنى دقيقة، تعرف مشكلة واحدة، تصلّحها، تـpush، تستنى تاني — لمشكلة كانت
هتظهر في نفس الـ run لو كمّل.

دلوقتي كل الفحوصات بتشتغل حتى لو اللي قبلها وقع، وفيه جدول ملخّص في آخر
الـ run:

```
| Check                   | Result   |
|-------------------------|----------|
| Lint                    | ✅ pass  |
| Type check              | ✅ pass  |
| Assets exist in public/ | ❌ FAIL  |
| Build                   | ✅ pass  |
| Internal links          | ❌ FAIL  |
```

**run واحد = كل المشاكل مرة واحدة.**

وكمان السكربتات بقت بتطلّع `::error::` annotations، فالمشاكل بتظهر كتنبيهات
على الـ run نفسه بدل ما تبقى مدفونة في اللوج.

## الأسباب المحتملة، مرتّبة

### 1. `check:assets` وقع — وده على الأرجح، وده **مقصود**

الفحص ده بيتأكد إن كل مسار `Assets/…` في الـ config موجود فعلاً في
`public/`. لو وقع، هو مش بيبلّغ عن bug في الكود — هو بيقولك **إيه الملفات
الناقصة**، وده بالظبط السؤال اللي بنلف حواليه من كام رسالة (هل الـ CV PDF
موجود ولا لأ؟).

اللوج هيقولك بالاسم. شغّله محلياً في تانية:

```bash
npm run check:assets
```

### 2. `check:links` وقع

أنا شغّلته على النسخة عندي وطلعت **صفر لينكات مكسورة غير الأصول** — بس
مفيش عندي `public/`، فكل مسارات `Assets/` بتبان ناقصة. عندك، بالمجلد
الحقيقي، النتيجة هتبقى دقيقة.

### 3. `lint` أو `type-check` وقعوا

الاتنين نضاف عندي، **بس أنا شغّلتهم على مجلد `app/` بس**. الريبو بتاعك فيه
ملفات مش معايا (`scripts/` القديمة، `.venv`، أي حاجة تانية). لو فيه ملف
قديم فيه خطأ lint، هيظهر دلوقتي لأول مرة.

### 4. الـ lock file

اختبرته: `npm ci` بالـ `package-lock.json` بتاعك مع `package.json` الجديد
**بيعدّي عادي**. فده على الأغلب مش السبب.

بس لو اللوج بيقول حاجة عن lockfile out of sync:

```bash
npm install
git add package-lock.json
git commit -m "chore: sync lockfile"
```

## شغّل نفس السلسلة محلياً قبل ما تـpush

الـ workflow بيشغّل نفس أوامر `npm run verify` بالظبط:

```bash
npm run verify
```

وده أسرع بكتير من إنك تستنى الـ CI كل مرة.

## ملحوظة عن الـ Deploy

في الصورة، **الـ Deploy نجح** والـ Verify هو اللي وقع. يعني الموقع اتنشر
عادي — الـ Verify بيشتغل جنبه مش قبله.

لو عايزه يوقف النشر لما الفحص يقع، ضيف في workflow النشر:

```yaml
jobs:
  deploy:
    needs: verify        # مش هينشر غير لو Verify عدّى
```

بس **متعملش ده دلوقتي** — استنى لحد ما الـ Verify يبقى أخضر الأول، وإلا
هتقفل النشر على نفسك.
